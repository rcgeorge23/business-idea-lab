# Calibration

Method version: see `method/VERSION`.

Before the method is trusted for routine use it must be calibrated against known cases.
Calibration is the acceptance test for the loop itself; it is not market validation of
any idea.

## What calibration must cover

1. **GeoNerd** (real, pre-existing case). The worker re-reads the GeoNerd evidence
   registers, verifies or challenges the seeded scorecard, and either keeps it at
   `validation-ready` (with the review request raised) or moves it down with reasons.
2. **At least two weak/rejected ideas** generated by the worker in the normal way. These
   exercise the hard filters and the kill path, including preserved reasons.
3. **One attractive-looking control** that should fail adversarial review. This tests
   that the adversarial pass and the reviewer are genuinely willing to kill something
   that looks good.
4. **Independent critique.** At least one DeepSeek-produced result is compared with a
   ChatGPT critique. The critique is recorded as a review response file per
   `method/review-policy.md`, and the worker must respond to it explicitly in a later
   run (changes accepted or disputed with evidence).
5. **Tuning.** Instructions, templates and thresholds are adjusted based on what
   calibration exposes. Material changes increment `method/VERSION` and themselves
   require a review request (trigger 2 in `method/review-policy.md`).

## Procedure

1. Human owner triggers a normal run: `scripts/run.sh` (after reviewing a dry run with
   `scripts/run.sh --dry-run`).
2. Worker processes queued reviews first (GeoNerd) and then performs its standard run per
   `method/run-protocol.md`, bounded to the fixture work where the run budget allows.
3. Human owner sends the generated review request(s) to ChatGPT and commits the response
   files under `reviews/`.
4. Worker responds to the review in the next run.
5. Human owner records what was learned in `retrospectives/`, and updates the status
   table below.

## Exit criteria

Calibration is complete when:

- [x] GeoNerd has a recorded review outcome and its state reflects it.
- [x] >=2 weak ideas were generated and killed through the documented path, with reasons
      preserved and a false-negative audit sampled correctly.
- [x] >=1 attractive control failed adversarial review or review with reasons recorded.
- [x] >=1 DeepSeek result was compared with a written ChatGPT critique, and the worker
      responded to it explicitly.
- [x] The first tuning pass is recorded in a retrospective, with any method changes
      versioned and review-requested.

All five criteria were met by 2026-09-21 (issue #6 response reconciliation; see the
status table). Later method reviews are now reconciled too: 1.4.0 was **approved** on
receipt of `reviews/2026-09-21-method-v1.4.0-chatgpt.md`; 1.5.0 was answered

implements the requested changes with a new review requested (issue #8). The only
outstanding reviews are the `wonkybox` kill-#15 false-negative audit and the method
1.6.0 request; neither blocks the calibration exit criteria.
