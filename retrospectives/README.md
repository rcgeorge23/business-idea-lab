# retrospectives/ — what the loop itself should learn

Written after a run (or a series of runs) to improve the method, wording of
prompts, calibration and thresholds — never to re-litigate an idea's score
outside the evidence process.

Suggested file name: `<YYYY-MM-DD>-<topic>.md`. Contents worth recording:

- What the run produced and what it cost (link the `runs/<id>/run.json`).
- Where the method, templates or instructions were ambiguous or wrong.
- Repeated failure modes (e.g. candidate generation drifting into duplicates,
  scores resting on one vendor page).
- Calibration observations, including any comparison against independent
  review.
- Concrete proposed method changes, each marked `proposed` until a human owner
  approves them.

Retrospectives are inputs to the next run's step 1; they are not authoritative
over `method/`.
